# SUMMARY (release-law review)

Method: read the brief, findings, earlier reservoir docs and the `61a4a50` code; ran four light Python analyses on existing outputs (no training): a volume/variance audit, a KGE decomposition of the full-population arms (both seeds), one-parameter offline extensions of the seasonal bucket at the 214 on-reach smoke dams plus matched controls (cap as NID-max-discharge fraction, free cap, inflow-driven T, storage-driven T, loss fraction, flood-pool spill), and a ceiling decomposition (per-gauge fit, a feature-limited 5-fold CV version of it, the ddrs-learned parameters simulated offline, gain by fitted T0 class, Nash cascades).

Headline: the release-law family adds little. Choosing the best extra term per dam on training years generalises to +0.006 at on-reach dams, a quarter of the bucket's own +0.021. The big losses are elsewhere: a feature-limited head could reach +0.015 to +0.017 on-reach; the parameters ddrs learned give +0.008 to +0.010 offline and +0.006 in the engine. 73 % of the offline gain sits at fitted T0 > 2 d, where the learned head recovers only 15 to 70 % (T0 > 20 d: fit +0.110, learned +0.016); learned T0 is a factor 3.6 short. KGE loss is 100 % the alpha term (r up, beta flat), i.e. the NSE objective, not the physics.

Top 5, ranked by (gain x confidence)/cost:

1. Let the head learn long memory: `warmup` 5 → 30 d, `rho` 90 → 180 d (config only), then `experiment.state_cache` (implemented in `src/data/store/state_cache.rs`, needs a continuous dam-arm run). Evidence: 73 % of the ceiling at T0 > 2 d, learned T0 3.6x short, 6 % vs 29 % above 5 d. Test: one smoke learned arm with warmup 30 / rho 180 (~2 h). Go if on-reach dNSE >= +0.010 and Spearman(learned, fitted T0) >= 0.55 with median ratio < 2.
2. Freeze-routing ablation: train only the release head with the routing head frozen at the off checkpoint. Evidence: undammed gauges lose −0.0011 / −0.0007 with intervals clear of zero, gamma wanders. Test: one smoke arm (~1 h), controls are 0 by construction. Adopt a two-stage schedule if dam gain >= 80 % of the joint arm's.
3. Additive dam row `K := K_reach + T`, `X := X_reach·K_reach/(K_reach+T)` (S19''/B19'' edit; today the row REPLACES the reach's routing so T = 1 h is faster than no dam). Evidence: check 1b failure (188 gauges, min 0.485, Spearman 0.55 with reach length); 44 of 214 on-reach dams are pass-through in the fit and lose 0.011 each with the learned params. Test: the original check 1b (T = 1 h, NSE > 0.999 everywhere) plus one smoke arm. Go if 1b passes and floor-class dams stop losing.
4. KGE via the objective: `experiment.loss.kind: nnse-kge` for both arms. Evidence: dammed dalpha −0.0086 (82 % down), r +, beta flat; alpha < 1 at 72 % of gauges before dams; no law tested restores variance (Nash cascade: +0.0003 KGE for −0.0008 NSE). Test: two config arms. Go if dam dKGE >= 0 with >= 70 % of the NSE gain kept.
5. Inflow-driven T, `T_{t+1} = T_seas·(I_t/I_ref)^c`, a fourth head output; linear in A (I_t is last step's state; Burn carries the q_t → T edge, no op change), after ablating the day-of-year terms (`seasonal: false`, config only; the phase flips between seeds, b sign agrees at 43 %). Evidence: best of the family offline (114/61, p 1e-4, 25 % of dams > +0.01, the only law raising KGE, +0.0015; flood control +0.0014). Test: two smoke arms. Go if dam-minus-control >= +0.002 clear of zero and KGE not down. Trap: the test phase resolves the head into a fixed table (`release_eval.rs`); a state-driven law needs `c` carried per dam.

No-go with evidence (do not re-open): cap as NID-max-discharge fraction (48/37, median 0; spillway design flow >> operating flow); free cap (controls 24/72, overfits, confirms research-status); flood-pool spill / two-bucket (64/44, null); Nash cascades (worse NSE); loss fraction (absorbs Q' volume bias: Spearman 0.51 with pass-through beta, controls with beta > 1.1 want it 23/3; it would be the model's only volume knob); uniform T0 scaling (x3: KGE −0.009); learned Muskingum X on dam rows (c1 >= 0 needs X <= dt/2K ≈ 0.02). No identity-row law is needed: every recommended law is linear in the solve.

What I think is wrong in the current implementation: (1) the dam row replaces reach routing, so the head cannot opt out; check 1b was re-specified around this instead of fixed; (2) `warmup: 5` with T0 up to 17 d scores each window's storage transient and pushes T0 short; (3) two unidentified seasonal parameters per dam are carried and reported; (4) the offline ceiling double-counts the dam reach (bucket on top of a series that already routes the reach), so check 4's "stays low" criterion used the wrong floor; (5) KGE is framed as a physics shortcoming when it is the objective.

## 2. What fits the one-solve-per-step structure
Any law whose coefficients at t+1 are functions of step-t state (q_t, I_t = (N q_t)_d + q'_d, S_t = T_t q_t) goes into A unchanged, because that state is known before the solve. Linear in A: seasonal T (today, S19''' storage-conserving trapezoid, B19''' returns dL/dT_{t+1} and dL/dT_t); inflow-driven T and storage-driven T (build T in `ArmedRelease::t_step_at` from `self.discharge_t`; op unchanged; Burn adds the q_t → T → op edge, O(n_dams) tape entries per step; invariant 4 untouched); a cap via T-lift `T_{t+1} = max(T0, (S_t + dt I_t)/Q_max)` (one-hour lag, subgradient switch); the additive dam row (S19''/B19'' edit: gk passes to the channel chain with weight 1 on dam rows, gx scaled by K_reach/(K_reach+T)). NOT linear: hard cap or threshold on q_{t+1}/S_{t+1} (identity row `A[d,:] = e_d`, b_d = R_d, storage carried outside, hand-written storage recursion in the backward); Nash cascades (extra rows, new CSR pattern; the `subdivision` pieces machinery is the existing way, rejected with reservoirs in `config.rs::validate_reservoirs`). Nothing recommended needs an identity row.
